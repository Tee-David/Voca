# Support

Voca is maintained as an open-source project, not as a guaranteed support service.

## Bugs

Use the GitHub bug-report form once the public repository is available. Include a minimal reproduction and environment details, and remove private document content, credentials and personal information from logs.

## Feature ideas

Use the feature-request form and start with the reading or contributor problem you want to solve. Proposals that introduce a required remote service should explain why the capability cannot remain optional.

## Security

Do not use public issues for undisclosed vulnerabilities. Follow `SECURITY.md`.

## Setup questions

Check the README, contributor quickstart, configuration guide and existing issues first. When asking for help, describe what you tried and include sanitized errors rather than screenshots or logs containing secrets.

## Private documents

Do not upload a private book or confidential document to a public issue to demonstrate a bug. Reduce the case to a synthetic fixture or describe the structural property that triggers the problem.
