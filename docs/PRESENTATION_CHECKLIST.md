# Public Presentation Checklist

A technically strong repository can still be difficult to understand. Complete this against the clean public candidate.

## Repository landing page

- [ ] One-sentence product description is immediately visible
- [ ] Problem is explained before implementation details
- [ ] Local-first promise is accurate and not overstated
- [ ] Supported document formats and major capabilities are easy to scan
- [ ] Architecture diagram renders correctly
- [ ] Setup commands are copyable and verified
- [ ] Security, privacy, contribution and roadmap links work
- [ ] License status is unambiguous

## Visual proof

- [ ] Hero screenshot uses safe/public-domain or synthetic content
- [ ] Reader screenshot demonstrates synchronized reading clearly
- [ ] Mobile/PWA visual is current
- [ ] Optional short demo uses copyright-safe material
- [ ] No screenshot exposes personal data, private document text, tokens or production admin UI

## GitHub metadata

- [ ] Repository description finalized
- [ ] Topics selected
- [ ] Social preview image prepared
- [ ] Issue forms render correctly
- [ ] Private vulnerability reporting enabled after public repository setup
- [ ] Default branch and release tags are intentional

## New-contributor perspective

- [ ] Open repository in a logged-out/private browser session
- [ ] Follow README without private context
- [ ] Confirm links do not point to inaccessible private resources
- [ ] Confirm no wording implies unsupported guarantees
- [ ] Confirm project identity is consistent across README, release notes and repository metadata
